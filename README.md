Some scripts put in the clipboard a prompt to give to an LLM. They are in the `step by step` folder.

`run.bat`, in the root, is the entry point. It starts `0_run_all`, which runs them all in a single terminal: after each script, it says what to paste and copy, waits, then runs the right next script. Typing the number of a script (2.5, ...) jumps to it, c copies the prompt again, w tells whether the clipboard still holds the prompt (nothing was copied since) or something else, which may be the answer of the LLM, q quits. It remembers where the user is: closed and started again, it asks the same question again.

1. `1.0_get_menu_prompt`: gives a prompt to get a vegan menu that satisfies all the daily nutrient needs in the table. The prompt contains the daily nutrient needs table, and product.csv when the user already has products, so that the menu is rather made of their foods. The script first asks in the terminal the options of the menu, each one answered by y or n: tell the LLM where the user lives, the menu must be as cheap as possible, as environmentally friendly as possible, as quick to prepare as possible, then a free text for anything else. Enter keeps the last answer. The prompt only tells the chosen ones, and so do the prompts that correct the menu (scripts 1.5 and 5). The answers and the address are in DB/menu_options.json, which is not in git: the address is changed there.
1.5. `1.5_copy_menu_then_check`: from the copied answer (the menu as a text, then its csv), the script saves the csv in menu.csv and the text in menu_description.txt, then gives a prompt to correct the menu, and to spot any inconsistency between the text and the csv. The prompt contains the daily nutrient needs table, the menu as a text and the menu.
2. `2.0_get_food_prompt`: gives a prompt to identify each food of the menu in food.csv from the SR Legacy 2018 from fdc.nal.usda.gov, or in food_manual.csv. The prompt contains the menu and food_manual.csv. The LLM writes one row per food of the menu, with the columns description, fdc_id and fdc_description (the description from USDA, to check if they correspond). A food that is in none of the two csv files has `new` as fdc_id.
2.5. `2.5_copy_foods_then_check`: from the copied food list, the script checks each fdc_description against the csv files, saves the IDs in menu.csv, then gives a prompt to correct the food list. The prompt contains the menu, the food list and food_manual.csv.
3. `3.0_get_ingr_prompt`: adds the foods marked `new` to food_manual.csv, and writes the new food list in new_food.csv: those foods, and every food of food_manual.csv that has no nutrient yet. Gives a prompt to get for each food of the new food list a list of ingredients. The prompt contains food_manual.csv and the new food list. If there is no new food, it says so, and the user goes to script 5.
3.5. `3.5_copy_ingr_then_check`: from the copied ingredient composition table, the script saves it in food_ingredient_manual.csv, then gives a prompt to correct it. If some of the ingredients are also food that are not in both csv files (`new` as ingredient_fdc_id), the script adds them in food_manual.csv and in the new food list, and the prompt asks for their ingredients. A food whose nutrients cannot be deduced from ingredients (a supplement, an isolate, ...) has `none` as only ingredient. The prompt contains the daily nutrient needs table, food_manual.csv, the new food list and the ingredient composition table. For each food in the new food list, the script deduces their nutrient composition from their ingredients, and updates food_nutrient_manual.csv.
4. `4.0_copy_nutr_if_given_then_check`: gives a prompt to correct the new rows in food_nutrient_manual.csv when the nutrient composition of a food can’t simply be the sum on all its ingredients. The prompt contains the daily nutrient needs table, the new food list, their ingredient composition and their nutrient composition. If the clipboard contains a nutrient table, the script first saves its rows in food_nutrient_manual.csv. The script checks if all nutrients from the daily nutrient needs table are present for each new food: the prompt asks for the missing ones.
5. `5.0_get_product_prompt`: gives a prompt to get, for each food of the menu that has no product yet, a real product the user can buy. The foods of the databases are generic ones: the product really bought may not have the same nutrients (a nutritional yeast is fortified with B12 or not). The prompt contains the daily nutrient needs table, the menu, and the nutrients the menu counts on each food for: the ones the food brings at least 20% of the total of the day of. The LLM writes two tables: the products (fdc_id, product, shop, price, package_amount, eco, source), then the nutrients that their label gives (product, nutrient_id, amount, source). If every food has a product, it says so, and the user goes to script 6. The products are not needed for the report: a food without product is counted as its generic food.
5.5. `5.5_copy_products`: from the copied answer, the script saves the products in product.csv and their nutrients in product_nutrient.csv. A product that its food already has (same description) is updated. Each food of the menu is counted as the product just given for it from now on (menu_product.csv).
6. `6.0_get_report`: compares the menu with the daily nutrient needs table, each food being counted with the nutrients given for its product, or else with those of its generic food. It says the price of the day, from the prices of the products. If the table is satisfied, it says so, and adds the menu to successful_menus.csv, with the options it was made with (the ones answered at script 1., without the address) and the product of each food. The text of the menu is saved in the successful_menu_descriptions folder, in a file named after the number of the menu. Otherwise, it first looks whether a product the user already has would make the menu satisfy the table when a food is counted as it instead, and offers to do so. If none does, it gives a prompt that makes the LLM correct what is wrong, with the first of three corrections that can fix the menu, from the cheapest for the user to the most expensive:
    1. the numbers of the products: the prompt lists the numbers behind the lacks and excesses that the user did not read on the product, to check them. This correction is only there when there are such numbers.
    2. other products for the same foods, that suit this menu better.
    3. the menu itself.

    The prompt contains the daily nutrient needs table, the menu with its products, the lack of nutrients and the excess in nutrients, the products of the foods of the menu, and the foods that bring the nutrients in lack or in excess. The user copies the whole answer: `0_run_all` sees from its tables whether it corrects products, and runs script 5.5 then script 6. again, or the menu, and runs script 1.5.

A product is one of the generic foods (fdc_id) as it is really sold. Its price is in euros for package_amount, which is in grams, or in doses for a supplement. Its eco level goes from A (the best) to E. Its source tells where the information comes from: the website the LLM read it on, `estimate` for what the LLM knows by itself, or `on site` for what the user read on the product. Each nutrient of a product has its own source. A menu is checked when each of its foods is a product whose information and nutrients were all read on site.

`menus.bat`, in the root, is the entry point to list the menus of successful_menus.csv. It starts `list_menus`, which first asks for the number of a menu, to show only that one. With Enter instead, it asks for each option whether the menus must have been made with it (y), or whether it does not matter (n), whether their foods must all be products read on site, and a text their other wishes must contain. It then shows the text and the foods of each menu that was made with all of them, with the product each food was counted as, its price of the day, and whether it is checked. Typing the number of one of those menus puts two csv tables in the clipboard: its foods with their ID, amount and product, the nutrients those foods are counted with (food ID, nutrient ID, name, unit, amount and source), only for the nutrients of the daily nutrient needs table, and its products.

The prompts that ask for a menu (scripts 1., 1.5 and 6.) tell the LLM to write it as a text first, meal by meal, with the amount of each food, then as a csv: the user copies the whole answer, and the script takes as the text all that is written before the csv.

The name of a script says what the user must copy before running it. The other scripts don’t look at what is in the clipboard.

When the prompt asks the LLM to go check the SR Legacy 2018 DB, it asks it to use its web search tool.

For the scripts 1.5, 2.5, 3.5 and 4., the user must run the script, paste the clipboard into the LLM, and if it says it is correct, go to the next script, otherwise copy the csv table it gives and do this again (run the script, paste, …).

The prompts tell the LLM to either say everything is correct, or write a table in the csv format easy to copy: the whole corrected table, except at script 4., where it only writes the rows to change or to add. The menu, daily nutrient needs table, new food list, etc… are in the csv format.

If the script finds an error, the prompt contains the error message and the user pastes it in the same discussion with the LLM. Otherwise, the given prompt is meant to be the start of a new discussion.

When the menu is corrected at script 6., a food whose description is unchanged keeps its ID: only the other ones are left to identify at script 2.

SR Legacy 2018 has no data for some nutrients (biotin, iodine, chromium, molybdenum, sulfur, and fluoride for most foods). At script 3.5, a nutrient that no ingredient of a food has data for is left out: script 4. asks the LLM for it. At script 6., a nutrient that at least half of the foods of the menu have no data for cannot be judged: it does not count as a lack.


This process allows the user to use its LLM subscription to the fullest instead of paying for API with a fully automatic solution. Here I use Gemini Pro.
